# CLAUDE.md — IO::Tty

## What is IO::Tty

IO::Tty is a CPAN distribution providing pseudo-tty allocation and terminal constants for Perl.
It is the foundation that Expect.pm and IPC::Run rely on for pty I/O.

- **IO::Tty** — Low-level XS module: pty allocation, terminal constants, winsize helpers
- **IO::Pty** — High-level Perl module: master/slave pty pairs, controlling terminal setup
- **IO::Tty::Constant** — Auto-generated terminal constants (from termios.h/termio.h)

POSIX-only. Windows is not supported (dies at `Makefile.PL` time; Cygwin works).

## Build & Test

```bash
perl Makefile.PL    # Probes system for pty support, headers, functions
make
make test           # ~4 seconds
prove -wlvmb t     # Verbose test run
make disttest       # Full distribution test (builds tarball, tests from it)
```

`Makefile.PL` is not a simple metadata file — it compiles C test programs to detect
available functions (`openpty`, `grantpt`, `ptsname`, etc.), headers, and terminal
constants. It generates `xssubs.c` and `Tty/Constant.pm` at configure time.

### Dependencies

- Perl >= 5.008008

## Key Architecture Details

### Tty.xs — Pty allocation

The XS code implements multiple pty allocation strategies, tried in order:
1. `openpty()` (if available)
2. `/dev/ptmx` + `grantpt`/`unlockpt`/`ptsname` (SVR4/POSIX)
3. `/dev/ptym/clone` (HP-UX)
4. `_getpty()` (IRIX)
5. `/dev/ptc` (AIX)
6. BSD-style `/dev/ptyXY` scanning (fallback)

The `open_slave()` function handles STREAMS module pushing on Solaris (`ptem`, `ldterm`)
and must use `_open_tty()` (not `IO::Tty->open()`) for this to work correctly.

### Pty.pm — Lifecycle

- `new()` calls `pty_allocate()` (XS), wraps both master and slave fds as Perl handles
- The slave is cached in `${*$pty}{'io_pty_slave'}`
- `close_slave()` closes and removes the cached slave; `slave()` can re-open it
- `DESTROY` only deletes the internal slave reference — does NOT force-close.
  Perl refcounting handles fd cleanup. Force-closing would break IPC::Run and
  other consumers that hold their own slave reference.

### Terminal constants

The full set of `TIOC*`, `TC*`, `V*`, `B*`, etc. constants is probed at configure time.
Constants that don't exist on the build system are set to `undef`.
Use `IO::Tty qw(CONSTANT_NAME)` or `IO::Tty::Constant::CONSTANT_NAME`.

## Testing Conventions

- Use `Test::More` with explicit `plan tests => N`
- Each test file covers one feature or behavior
- Tests allocate real ptys — no mocking of system calls
- Use `SKIP` blocks for platform-specific features (e.g., `isatty` on master varies by OS)
- MANIFEST must include all `t/*.t` files for `disttest` to pass

## Release Process

Releases are done by the human maintainer only. Do not:
- Bump `$VERSION` in Tty.pm or Pty.pm
- Update ChangeLog
- Modify MANIFEST (it reflects the canonical file list)

The version in `Pty.pm` tracks `Tty.pm` (`$VERSION = '1.27'; # keep same as in Tty.pm`).
`Tty/Constant.pm` gets its version from `MM->parse_version('Tty.pm')` at configure time.

## Platform Considerations

- **BSD visibility macros**: Different BSDs need different feature-test macros
  (`__BSD_VISIBLE`, `_BSD_SOURCE`, `_NETBSD_SOURCE`). DragonFly BSD needs
  `__DragonFly__` guards parallel to `__FreeBSD__`.
- **Perl 5.40+**: Stricter ioctl overflow detection. Pre-allocate ioctl buffers
  with actual content (e.g., `" " x 1024`), not empty strings.
- **POSIX::fcntl()**: Broken on Perl 5.42 (returns undef for all fds).
  Use `POSIX::dup($fd)` to check if an fd is open.
- **NetBSD**: Kernel revokes slave pty fd when master is closed.
  FreeBSD/OpenBSD do not. Tests must probe dynamically.
- **O_RDWR/O_NOCTTY in Pty.pm**: Come from `use IO::File` which exports all
  Fcntl constants. Not a missing import.
- **strlcpy**: Check both `HAVE_STRLCPY` (our detection) and `HAS_STRLCPY`
  (Perl's Config.pm) for robustness.

GitHub Actions workflow (`.github/workflows/testsuite.yml`):
- Ubuntu (system perl) + disttest
